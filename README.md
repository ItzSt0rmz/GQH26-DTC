## Project Overview

This project implements a fully FPGA-resident UART trading-signal processor for the GQH hardware challenge. Each incoming packet contains two item/price pairs, and the FPGA routes each item by its ID into a per-item 16-sample moving-average detector. The design compares the current price against the moving average and emits `NONE`, `SELL`, or `BUY` actions for both slots while preserving packet index and slot ordering in the response.

All packet parsing, state tracking, algorithmic computation, and UART response generation occur on the FPGA. No host-side software participates in the judged execution path.

## FPGA Implementation

The FPGA design is implemented directly in VHDL as a small microcoded datapath:

- `top.vhd`: top-level entity; UART RX/TX, packet assembly, response framing and control sequencing, driven by the microcode ROMs
- `roms.vhd`: generated ROM tables (timing, RX state machine, idle, sequencer, control words, ALU) that implement the 16-sample moving-average / crossing logic
- `bram1.vhd`: small block-RAM wrapper holding per-item window, sum, previous price and last action
- `gen_vectors.py`: Python reference model that generates test vectors (`testbench/vectors.txt`); local tooling only, not part of the synthesized design

The UART transmitter keeps an idle gap between response bytes for BL616 compatibility.

During the official run, no team-supplied host software is executed. All UART parsing, state, algorithmic computation, and response generation happen on the FPGA.

## Fixed UART Interface

The design follows the official interface exactly:

```text
PC -> FPGA:
[index16][item1_8][price1_16][item2_8][price2_16]

FPGA -> PC:
[index16][item1_8][action1_8][item2_8][action2_8][reserved16]

reserved = 0x0000

ITEM_A = 0x11
ITEM_B = 0x22

NONE = 0x00
SELL = 0x01
BUY  = 0x02

UART = 115200 baud, 8N1, LSB first
Packet size = 8 bytes each direction
Multi-byte fields = big-endian
Routing = by item ID; response mirrors request slot order
```

## External Libraries / IP / Starter Code

None. The design is implemented directly in VHDL from scratch using the organizer-provided board constraints and challenge protocol specification. `roms.vhd` is generated from our own Python model (`gen_vectors.py` / microcode tables).

## Known Limitations

- The design is specialized to the Tang Nano 20K and the challenge protocol; it is not a general-purpose trading engine.
- All packet processing is done on the FPGA; there is no host-side fallback or debug path during official judging.
- The UART transmit path includes a minimal inter-frame spacing workaround to remain compatible with the BL616 USB-UART bridge.
- The project is validated using the provided UART test scripts and challenge data only.
